# ShorelandsMods

Casual mods for Shorelands: one BepInEx plugin, the mod host, that loads mods made of Lua scripts, pictures and
sounds. Players drop a mod folder into the game's `mods` folder and it loads within a second or two, also while
the game runs. Mod authors need a text editor and, for pictures, an image editor; no C#, no build.

What a mod can do:

- **Art packs**: replace the game's textures by name, item icons and koi icons by id.
- **Sound packs**: replace the game's sounds and music by event name.
- **Cues**: own pictures and sounds for the fishing moments (bite, nibble, tug, ...).
- **Lua mods**: HUD texts, icons and bars, windows with lists and buttons, settings on the game's settings page,
  chat commands and chat highlights, notices, timers, sounds, saved data, and text files for OBS.

Mods change only what you see and hear on your own PC. They cannot press anything for you, send anything to the
server, or read what would give an advantage (fishing timing, market stalls, other players). Each Lua call has a
time and memory budget, and a mod can only read and write inside its own folders.

It is a fan-made mod, not made or supported by the game's developer, so please don't report its problems to the
game.

## Requirements

- **Shorelands on 64-bit Windows**, tested with Playtest 0.69i.
- **[BepInEx 5.4.23, x64](https://github.com/BepInEx/BepInEx/releases)** installed in the game folder.

The Lua runtime ([Lua-CSharp](https://github.com/nuskey8/Lua-CSharp)) is included.

## Install

1. Close the game and open its folder (Steam: right-click the game, *Manage*, *Browse local files*).
2. If you don't have BepInEx yet, unzip it there so that `winhttp.dll` and `BepInEx\` sit next to
   `Shorelands.exe`. Start the game once and close it, so BepInEx creates its folders.
3. Download the zip from the [latest release](../../releases/latest) and unzip it into the same folder, merging
   folders. You should now have `BepInEx\plugins\ShorelandsMods\ShorelandsMods.dll` and a `mods\` folder with
   the nine example mods and `_guide.html`.
4. Start the game. Its settings now have a **Mods** page (menu button top right, *Settings*, *Mods*); the chat
   command `/mods` lists what is loaded.

To uninstall, delete `BepInEx\plugins\ShorelandsMods`. Everything mods changed goes back to the game's own at the
next start. To remove the mods and what they saved too, also delete `mods\`, `mods_data\`,
`BepInEx\config\com.zerfl.shorelands.mods.cfg` and `BepInEx\config\mods.*.cfg`.

## Making mods

The author guide is online at **https://zerfl.github.io/ShorelandsMods/** (source: [guide/guide.md](guide/guide.md)); the release zip has it as `mods\_guide.html`. Start with
*Your first mod in ten minutes*. At the first start the game writes `mods\_api.txt` (every function a Lua mod can
use) and `mods\_names.txt` (every name a picture, sound or cue can replace).

The [examples](examples) are the nine mods the release ships:

| Mod | What it shows |
| --- | --- |
| `example` | The starter mod: every callback, with a comment saying when it runs. Copy it to start your own. |
| `chat_helper` | Chat timestamps, highlights and a `/stats` command. |
| `koi_checklist` | A window with every koi, filters, a search, and a tooltip line. |
| `offering_reminder` | A countdown for the offering round, notices, a weather line. |
| `session_stats` | A HUD panel with what you earned this session. |
| `stream_ticker` | Text files for OBS. |
| `icon_pack` | New item and koi icons (pictures only). |
| `sound_pack` | New sounds and a fishing bite cue (sounds only). |
| `ui_skin` | A UI theme and a cursor (pictures only). |

The art and sounds of `icon_pack`, `sound_pack` and `ui_skin` are generated by the scripts in
[examples/_tools](examples/_tools) (Python; `sound_pack.py` also needs numpy, Pillow and ffmpeg).

## Building from source

Requires 64-bit Windows, the [.NET SDK](https://dotnet.microsoft.com/download) 10+, the game with BepInEx
installed (the build compiles against their assemblies) and, for the package, Python 3. Pass the game folder as
below, or set `SHORELANDS_DIR` instead.

```
dotnet build src -c Release -p:GameDir="C:\Program Files (x86)\Steam\steamapps\common\Shorelands Playtest"
dotnet run --project tests -c Release -p:GameDir="..."
powershell -ExecutionPolicy Bypass -File tools\release.ps1 -GameDir "..."
```

These build `src\bin\Release\ShorelandsMods.dll` (the Lua-CSharp DLLs it needs go to `src\bin\Release\lib`), run
the tests (`ALL PASS` at the end; they run the host's core without the game), and package
`dist\ShorelandsMods-<version>.zip`. The package script also checks the formatting, the built DLL and the zip's
contents. The version is `VersionPrefix` in `src\ShorelandsMods.csproj`.

Code is formatted with [CSharpier](https://csharpier.com): `dotnet tool restore`, then `dotnet csharpier format .`
before committing; CI runs `dotnet csharpier check .`.

`src\Core` is the host without Unity (mods, Lua sandbox, budgets, settings, assets, UI layout), which the tests
compile directly; `src\Game` connects it to the game. Version history: [CHANGELOG.md](CHANGELOG.md).
